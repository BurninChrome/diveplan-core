# Summary

The ZH-L16 tables were validated cell by cell against two independent
references: Bühlmann's own derivation formulas, and the published ZH-L16C
table. **Half-times, all `b` coefficients, and every helium coefficient are
correct.** The nitrogen `a` column is not.

- `zh_l16C` differs from published ZH-L16C at **11 of 96 cells**, all in
  nitrogen `a`, compartments 5–15. Ten are *higher* than published, meaning
  **less conservative**.
- `zh_l16A` is not ZH-L16A. It deviates from the formula that *defines* that
  variant at four compartments, carrying what appear to be ZH-L16B values.
- `zh_l16B` matches no published set.

The equations that consume these tables are correct — see
[the validation record](/decisions/2026-07-25-model-validation.md). This is a
data defect, not a math defect.

# Reference basis

Bühlmann derived the ZH-L16A coefficients from the half-times:

```
a = 2 bar / ∛(t½)          b = 1.005 − 1/√(t½)
```

ZH-L16A **is** the set these formulas produce — that is its definition. B and C
are A with the nitrogen `a` values manually lowered in the middle compartments,
because, in Baker's words, *"the mathematically-derived set A was found
empirically not to be conservative enough in the middle compartments … set B
(slightly more conservative) is suggested for table calculations and set C
(somewhat more conservative) is suggested for use with in-water decompression
computers."*

# Finding 2 — the variant labels do not match the variants

Testing `zh_l16A` against the formula that defines ZH-L16A:

| t½ | `zh_l16A` | formula-derived A | verdict |
|---:|---:|---:|---|
| 38.3 | 0.5600 | 0.5933 | mismatch |
| 54.3 | 0.4947 | 0.5282 | mismatch |
| 77.0 | 0.4500 | 0.4701 | mismatch |
| 305.0 | 0.2850 | 0.2971 | mismatch |

The other twelve rows match the formula to four decimals. The four that do not
carry the values published for **ZH-L16B**. So the table labelled `zh_l16A` is,
at least in part, ZH-L16B.

Laid side by side, the three repo tables sit between the true A and the true C:

| t½ | formula A | repo A | repo B | repo C | published C |
|---:|---:|---:|---:|---:|---:|
| 27.0 | 0.6667 | 0.6667 | 0.6667 | 0.6491 | **0.6200** |
| 38.3 | 0.5933 | 0.5600 | 0.5505 | 0.5316 | **0.5043** |
| 54.3 | 0.5282 | 0.4947 | 0.4858 | 0.4681 | **0.4410** |
| 77.0 | 0.4701 | 0.4500 | 0.4443 | 0.4301 | **0.4000** |
| 109.0 | 0.4187 | 0.4187 | 0.4187 | 0.4049 | **0.3750** |

The internal ordering A ≥ B ≥ C holds with no violations, so the tables are
self-consistent — they are simply all shifted toward the permissive end. The
pattern is consistent with the three sets having been generated by
interpolation rather than transcribed from the source.

# Finding 3 — the 4.0-minute compartment's `b` is unexplained

Row 0 of `zh_l16C` (t½ = 4.0 min) carries `b = 0.5240`. The formula gives
`1.005 − 1/√4 = 0.5050`, and 0.5050 is the published value.

This is not one of the two documented departures from the formula. Those are
compartments 4 and 5 — *"the b values calculated do not precisely correspond to
those used by Bühlmann for tissue compartments 4 (0.7825 instead of 0.7725) and
5 (0.8126 instead of 0.8125)"* — and this repository reproduces both of those
correctly. Compartment 1 has no such exemption, so 0.5240 has no source.

The 4.0-minute row is also the one that only `zh_l16C` has; it is the row
missing from A and B, which is what makes them
[one initialiser short](/findings/zh-l16ab-phantom-compartment.md).

# Impact

Currently **latent**: the CLI runs ZH-L12, so no shipped output is affected. See
[the ZH-L12/ZH-L16C finding](/findings/dive-uses-zh-l12-not-zh-l16c.md).

Were ZH-L16C selected, the affected compartments are the slow ones, so short
recreational dives are unchanged — the fast compartments that control them match
published values exactly. The error appears on **long exposures**, which is
where compartments 5–15 become limiting:

| Exposure | repo ceiling | published ceiling | repo shallower by |
|---|---:|---:|---:|
| 30 m, 30 min | 2.77 m | 2.77 m | 0.00 m (cpt 3 controls) |
| 30 m, 120 min | 9.19 m | 9.42 m | **0.23 m** |
| 50 m, 120 min | 20.94 m | 21.18 m | **0.24 m** |
| 15 m, 360 min | 2.72 m | 2.98 m | **0.27 m** |
| 50 m, 600 min | 27.69 m | 27.96 m | **0.27 m** |

A consistent ~0.25 m of missing conservatism on decompression dives — modest in
isolation, but systematic, in the unsafe direction, and present in the variant
specifically intended for real-time dive computers.

It also means [the test suite](/tooling/test-suite.md)'s 147 ZH-L16C runtime
checks validate a table that is not ZH-L16C. Its named-value assertions
(`cpt1 N2 a = 1.2599`, `cpt16 N2 a = 0.2327`) happen to test two of the rows
that *are* correct.

# Proposed fix

**Not applied.** Replace the nitrogen `a` column of all three tables with the
published values, and correct `zh_l16C` row 0's `b` to 0.5050:

- `zh_l16A` ← the formula-derived set (it is defined by the formula, so it can
  be generated and checked programmatically).
- `zh_l16B`, `zh_l16C` ← published values.

Source the numbers from a published table rather than another implementation,
per [the playbook](/playbooks/add-a-constant-table.md). Resolving
[the phantom-compartment defect](/findings/zh-l16ab-phantom-compartment.md) at
the same time is sensible — both are edits to the same rows of the same file.

Add a test asserting the formula relationship, which pins A exactly and bounds
B and C:

```c
for (i = 0; i < ZH_L16_NR_COMPARTMENTS; i++) {
    double a_calc = 2.0 / cbrt(zh_l16A[i].n2_h);
    double b_calc = 1.005 - 1.0 / sqrt(zh_l16A[i].n2_h);
    ASSERT_NEAR(a_calc, zh_l16A[i].n2_a, 1e-3, "ZH-L16A a follows 2*t^(-1/3)");
    if (i != 4 && i != 5)   /* documented departures */
        ASSERT_NEAR(b_calc, zh_l16A[i].n2_b, 1e-3, "b follows 1.005 - t^(-1/2)");
    ASSERT_TRUE(zh_l16A[i].n2_a >= zh_l16B[i].n2_a &&
                zh_l16B[i].n2_a >= zh_l16C[i].n2_a, "conservatism A >= B >= C");
}
```

The first assertion fails today at four compartments.

# Impact of fixing

No change to any current output, since nothing loads these tables. Ceilings
would deepen by up to ~0.27 m on long exposures once ZH-L16C is adopted. The
ZH-L16C named-value tests continue to pass; new formula-based tests would need
to be added alongside.
