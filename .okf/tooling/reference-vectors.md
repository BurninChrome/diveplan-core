# Why two mechanisms

They answer different questions and must not be merged.

| | Conformance vectors | Regression baseline |
|---|---|---|
| Question | Is the model **correct**? | Has the output **changed**? |
| Source of truth | Published theory | Today's binary |
| Location | `test/vectors/*.tsv` | `test/baseline.sha256` |
| Runner | `test_vectors` (via `make check`) | `test/baseline.sh check` |
| Changes when a bug is fixed | **No** — the bug was always a deviation | **Yes** — must be re-recorded |
| Contains known defects | No | **Yes, deliberately** |

Keeping them apart matters because a golden file recorded from buggy output
quietly becomes the specification once nobody remembers what it was for. That is
the exact failure mode this project already suffered with `doc/api.md`. The
vectors are the authority; the baseline is a tripwire.

# Conformance vectors

465 vectors across seven files, generated by `test/vectors/gen_vectors.py` — an
**independent implementation of the published equations** that never imports,
links against, or shells out to `libbuhlmann`. That independence is the whole
point: [the existing 202 assertions](/tooling/test-suite.md) check the library
against its own formulas restated in the test, which cannot catch a wrong
formula because both sides agree.

| File | Vectors | Checks |
|---|---:|---|
| `alveolar.tsv` | 90 | [`ventilation()`](/components/alveolar.md) across pressures, all three RQs |
| `haldane.tsv` | 72 | [Constant-pressure loading](/components/haldane.md) at 0/1/2/3 half-times, on- and off-gassing |
| `schreiner.tsv` | 80 | [Ramp loading](/components/schreiner.md), descent and ascent, `rate=0` reducing to Haldane |
| `ceiling.tsv` | 48 | [Combined-gas ceiling](/domain/m-values-and-ceiling.md) by the Bühlmann blend rule |
| `gradient-tolerance.tsv` | 108 | [GF-adjusted tolerance](/domain/ascent-and-stop-scheduling.md) at GF 1.00 → 0.30 |
| `ndl.tsv` | 18 | [NDL](/domain/no-decompression-limit.md) by bisection on the ceiling crossing |
| `zh-l16-derivation.tsv` | 49 | [Coefficients](/components/tissue-constant-tables.md) against `a = 2/∛t½`, `b = 1.005 − 1/√t½` |

# What they found

Exactly the picture [the validation record](/decisions/2026-07-25-model-validation.md)
predicted, now enforced continuously rather than asserted once:

```
alveolar.tsv               90 checked    0 deviating   ok
haldane.tsv                72 checked    0 deviating   ok
schreiner.tsv              80 checked    0 deviating   ok
ceiling.tsv                48 checked   24 deviating   known deviation
gradient-tolerance.tsv    108 checked   90 deviating   known deviation
ndl.tsv                    18 checked   16 deviating   known deviation
zh-l16-derivation.tsv      49 checked   11 deviating   known deviation
```

**The equations pass every vector. All 141 deviations are data or missing API.**
That is the same conclusion reached three times by different methods, and it is
now a build artefact rather than a claim in a document.

# Expected failures, and the property that matters

`test/vectors/expected-failures.txt` records per file how many vectors deviate
and why, each pointing at its finding. CI stays green on known defects and fails
on new ones.

The runner also **fails when deviations are fewer than allowed**:

```
ndl.tsv    18 checked   16 deviating   20 allowed   FIXED - update expected-failures.txt
```

This is deliberate and is the mechanism that ties the vectors to the roadmap.
Fixing [the NDL defect](/findings/nodecotime-overestimates-ndl.md) turns the
build red until `expected-failures.txt` is updated in the same change — so a fix
cannot land while claiming more or less than it delivered. **Each finding fixed
is a number decreased, usually to zero, and then a line deleted.**

Current allowances map one-to-one onto findings:

| File | Allowed | Finding |
|---|---:|---|
| `ceiling.tsv` | 24 | [getCeiling vs compartment_mvalue](/findings/ceiling-vs-mvalue-divergence.md) |
| `gradient-tolerance.tsv` | 90 | no GF primitive — [scope gap](/domain/ascent-and-stop-scheduling.md) |
| `ndl.tsv` | 16 | [nodecotime over-reports](/findings/nodecotime-overestimates-ndl.md) |
| `zh-l16-derivation.tsv` | 11 | [ZH-L16 coefficients](/findings/zh-l16-a-coefficients-nonstandard.md) |

# Regression baseline

`test/baseline.sh` runs all 39 logs in `test/xml/` through
[`parse_dive.py`](/tooling/parse-dive.md) and `src/dive`, and stores a SHA-256
of each dive's full 36-field output. Any drift in any compartment shows.

```sh
./test/baseline.sh check     # CI runs this
./test/baseline.sh record    # deliberate, alongside an approved change
```

It finally puts the corpus to work — 39 real profiles with genuine ascent rates
and multi-level structure that `gen_dive.py`'s square profiles cannot produce,
[previously unused by any test](/tooling/test-suite.md).

**Never re-record to turn a red build green.** A diff means either an intended
model change, in which case the baseline belongs in the same commit, or a
regression.

# Limitations

**The tables are only checked against the derivation formula.** `gen_vectors.py`
parses the constants out of `src/*.c` rather than embedding them, so a table
edit is picked up — but the values are validated against `a = 2/∛t½`, not
against a published table held independently. This is why
[`zh_l12` remains unverified](/findings/zh-l12-unverified.md): it has no
derivation formula, so there is nothing to check it against.

**The baseline pins the demo, not the library.** It exercises
[`src/dive`](/components/dive-cli.md), which is a
[demonstration harness](/getting-started.md). A library-level change invisible
through that pipeline — a new primitive, a signature change — will not show up.

**NDL tolerance is 0.5 minutes**, coarser than the model's precision. The search
is iterative and its granularity is not a property worth pinning.
